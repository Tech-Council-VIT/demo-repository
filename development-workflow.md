# Development workflow

## Branches
- `main`: stable code.
- `feat/<short-name>`: functionality.
- `fix/<short-name>`: bug fixes.
- `docs/<short-name>`: documentation.

## Pull requests
- Keep PRs focused.
- Link the issue being addressed.
- Include tests and screenshots where relevant.
- Obtain an independent review.
- Resolve review conversations.
- Merge only after required CI checks pass.

On private repositories under GitHub Free, these are team process expectations rather than enforceable
branch protection requirements.
